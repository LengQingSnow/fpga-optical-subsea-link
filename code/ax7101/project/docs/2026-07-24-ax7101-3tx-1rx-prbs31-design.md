# ax7101 Three-TX One-RX PRBS31 Ethernet Test Design

## Goal

Build an ax7101 hardware self-test in which Ethernet ports 1, 2, and 3
transmit continuous PRBS31 test frames at 1000BASE-T line rate. Ethernet
port 4 is connected to one transmitter at a time and keeps independent error
statistics for all three sources.

## Physical Interface

The ax7101 uses four RTL8211EG PHYs in 8-bit GMII mode. The design reuses the
pinout and MDIO access from the ALINX `ethernet_test` project.

- System clock: 200 MHz differential input.
- GMII transmit clock: 125 MHz forwarded from the FPGA to each PHY.
- GMII receive clock: supplied independently by each PHY.
- PHY reset: held low for at least 20 ms, then released.
- MDIO: reads each PHY link state and negotiated speed.
- Transmit traffic is enabled only when the corresponding PHY reports a
  1000BASE-T link.

Port 4 is connected directly to port 1, 2, or 3. Combining three full-rate
transmitters through a switch is outside this test because a single 1 Gb/s
receiver cannot accept 3 Gb/s of aggregate traffic.

## Ethernet Frame

Each transmitter sends standard maximum-size Ethernet frames:

| Field | Bytes | Value |
|---|---:|---|
| Preamble | 7 | `55` |
| SFD | 1 | `D5` |
| Destination MAC | 6 | `02:00:00:00:00:04` |
| Source MAC | 6 | `02:00:00:00:00:01/02/03` |
| EtherType | 2 | `88B5` |
| Test header | 16 | Magic, version, source, header length, sequence, PRBS length |
| PRBS31 data | 1484 | Same pattern on all three ports |
| Ethernet FCS | 4 | CRC32, little-endian on GMII |
| Inter-frame gap | 12 | GMII idle bytes |

The PRBS31 polynomial is `x^31 + x^28 + 1`, with seed
`31'h7fff_ffff`. It is restarted at the beginning of every frame so that all
three ports carry identical test data. A later data-source module can replace
the PRBS generator without changing the Ethernet transmitter or receiver.

The 1500-byte Ethernet payload contains this 16-byte header:

| Offset | Bytes | Meaning |
|---|---:|---|
| 0 | 4 | ASCII `AX71` |
| 4 | 1 | Protocol version `1` |
| 5 | 1 | Source port `1..3` |
| 6 | 2 | Header length `16`, network byte order |
| 8 | 4 | Per-port frame sequence, network byte order |
| 12 | 2 | PRBS length `1484`, network byte order |
| 14 | 2 | Reserved, zero |

## Receiver Statistics

Port 4 identifies the source from both the source MAC address and test header.
It maintains three independent sets of counters:

- received valid test frames;
- FCS-error frames;
- sequence gaps;
- PRBS bit errors;
- PRBS bits checked.

It also maintains global malformed-frame and GMII `RX_ER` counters. PRBS bit
errors are counted with an 8-bit population count. The reported BER for port
`N` is:

```text
bit_error_count[N] / bits_checked_count[N]
```

Sequence gaps measure missing Ethernet frames. They are separate from BER
because a frame lost before reception has no received bits to compare.

Counters cross from port 4 `RXC` into the 200 MHz system clock as coherent
snapshots and are exposed through a 20-probe Vivado ILA. Replacing the cable
does not clear counters; the external reset button or FPGA reprogramming
clears them.

## Verification

Six self-checking simulations verify:

1. MDIO direction control and state completion.
2. Gray-counter and statistics clock-domain crossings.
3. PHY reset timing and synchronized release.
4. PRBS31 known sequence and Ethernet CRC32.
5. Frame layout, IFG, source identity, and identical three-port PRBS data.
6. Source-specific counters, bit/FCS error injection, and sequence gaps.

The Vivado build must finish with nonnegative setup and hold slack, no DRC
errors, and a generated `.bit` and `.ltx`.
